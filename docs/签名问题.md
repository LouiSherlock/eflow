未签名 APK（unsigned.apk）。


说明 Tauri 已经成功完成了 Release 构建，但是还没有对 APK 进行数字签名。

Android 安装正式 APK 时需要有效签名，因此你需要给它签名后再安装。

## 一、生成 Android 签名密钥

先确保电脑安装了 JDK，然后在 PowerShell 执行：

```
keytool -genkeypair -v `
  -keystore release.jks `
  -alias tauri `
  -keyalg RSA `
  -keysize 2048 `
  -validity 10000
```

按照提示输入：

- Keystore 密码
- 姓名或组织信息
- 国家代码
- 确认信息

最后会生成：

```
release.jks
```

重要： 这个文件和密码一定要备份。以后更新同一个 Android 应用，需要继续使用兼容的签名密钥。

## 二、给现有 APK 签名

不需要重新编译，可以先给刚才生成的 APK 签名。

找到 Android SDK Build Tools 中的 `apksigner.bat`：

```
Get-ChildItem "$env:LOCALAPPDATA\Android\Sdk\build-tools" -Filter apksigner.bat -Recurse
```

假设找到的版本是 `36.0.0`，执行：

```
$APKSigner = "$env:LOCALAPPDATA\Android\Sdk\build-tools\36.0.0\apksigner.bat"

$UnsignedAPK = ".\src-tauri\gen\android\app\build\outputs\apk\universal\release\app-universal-release-unsigned.apk"

& $APKSigner sign `
  --ks ".\release.jks" `
  --ks-key-alias tauri `
  --out ".\app-release.apk" `
  $UnsignedAPK
```

执行时输入之前创建的 Keystore 密码。

## 三、验证签名

```
& $APKSigner verify --verbose ".\app-release.apk"
```

如果显示：

```
Verifies
```

说明签名成功。

## 四、安装到手机

手机开启 USB 调试，连接电脑：

```
adb devices
```

安装：

```
adb install -r .\app-release.apk
```



成功

&#x20;现在应该可以正常安装了。



## 五、让以后每次构建自动签名（推荐）

`src-tauri/gen/android/app/build.gradle.kts` 已接入条件式自动签名：只要存在
`src-tauri/gen/android/keystore.properties`，release APK 就会自动签名；没有该文件时
构建不会报错，但产物仍是未签名 APK。

### 1. 创建 `src-tauri/gen/android/keystore.properties`

仓库中提供了模板，复制后把 `CHANGE_ME` 换成你的 keystore 密码：

```powershell
Copy-Item src-tauri/gen/android/keystore.properties.example `
  src-tauri/gen/android/keystore.properties
```

```properties
password=你的密码
keyAlias=tauri
storeFile=../../../../release.jks
```

- 该文件已被 `src-tauri/gen/android/.gitignore` 忽略，不会提交到 Git。
- `storeFile` 相对 `src-tauri/gen/android/app/` 解析，四个 `..` 回到项目根目录；也可以直接写绝对路径。
- store 密码与 key 密码使用同一个 `password` 值。
- `release.jks` 已被根目录 `.gitignore` 的 `*.jks` 规则忽略。

### 2. 构建脚本中的配置

`build.gradle.kts` 会先读取属性文件，缺少必要字段时直接给出明确错误：

```kotlin
import java.io.FileInputStream
import java.util.Properties

val keystorePropertiesFile = rootProject.file("keystore.properties")
val keystoreProperties = Properties().apply {
    if (keystorePropertiesFile.exists()) {
        FileInputStream(keystorePropertiesFile).use { load(it) }
    }
}
val hasReleaseKeystore = keystorePropertiesFile.exists()
if (hasReleaseKeystore) {
    listOf("keyAlias", "password", "storeFile").forEach { key ->
        check(keystoreProperties.getProperty(key) != null) {
            "Missing '$key' in ${keystorePropertiesFile.absolutePath}"
        }
    }
}
```

`signingConfigs` 和 release 构建类型只在文件存在时启用：

```kotlin
signingConfigs {
    if (hasReleaseKeystore) {
        create("release") {
            keyAlias = keystoreProperties.getProperty("keyAlias")
            keyPassword = keystoreProperties.getProperty("password")
            storeFile = file(keystoreProperties.getProperty("storeFile"))
            storePassword = keystoreProperties.getProperty("password")
        }
    }
}

buildTypes {
    getByName("release") {
        if (hasReleaseKeystore) {
            signingConfig = signingConfigs.getByName("release")
        }
        // ...
    }
}
```

之后执行 `pnpm tauri android build` 生成的 release APK 会自动签名，无需再手动运行 `apksigner`。

### 3. 验证签名配置

```powershell
cd src-tauri\gen\android
.\gradlew.bat :app:signingReport
```

输出中 `universalRelease` 的 `Config` 为 `release`、`Store` 指向 `release.jks`、`Alias` 为 `tauri`，即表示配置生效。没有 `keystore.properties` 时这里会显示 `Config: none`。

注意：`keystore.properties` 和 `release.jks` 都不要提交到 Git；换电脑或 CI 构建时重新生成该文件即可。

官方文档：[Tauri Android Code Signing](https://v2.tauri.app/distribute/sign/android/)
